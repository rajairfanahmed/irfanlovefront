# Design Review Checklist

- [ ] One recommended design direction is clear and justified.
- [ ] The design is product-specific and not a generic category template.
- [ ] Every route has a clear purpose, audience, content hierarchy, and primary action.
- [ ] Important user flows and recovery paths are specified.
- [ ] Loading, empty, error, success, and permission states are included where relevant.
- [ ] Backend routes, methods, request fields, response fields, and errors match actual contracts.
- [ ] Unavailable contracts are marked pending rather than invented.
- [ ] Mobile composition is designed from the beginning.
- [ ] Semantic HTML, keyboard use, focus, and contrast are addressed.
- [ ] Motion has a purpose and a reduced-motion alternative.
- [ ] Public page rendering and metadata requirements are included.
- [ ] Media and performance budgets are documented.
- [ ] Specialist specifications do not contradict each other.
- [ ] Reference decisions are traceable to their source.
- [ ] All assumptions and conflicts are visible.
