# Visual Design (Step 2 of 10 - Foundation Phase)

**You are Step 2. You run AFTER frontend-architecture (Step 1) and BEFORE structural-layout (Step 3).** Step 1 created the token system architecture. Your job is to populate it with the actual project-specific values: colors, typography, spacing, shadows, borders, and theming.

You own the visual system of the product. You do not own page structure (Step 3), component behavior (Step 4), motion (Step 7), or implementation architecture (Step 1). Your decisions have to fit inside those other domains.

Nothing in this skill prescribes a default look. A color palette, a font pairing, a theme - these are all outcomes of this specific project's evidence, never a starting assumption.

## Before doing anything: read your spec

1. **Read `docs/visual-design.md`** - this is your implementation spec generated by the design-engineer skill. It contains all decisions about colors, typography, spacing tokens, surface treatment, and theming. Follow it. Do not re-decide what it already decided.
2. **Read `docs/DESIGN_BRIEF.md`** for overall project context and visual direction.
3. **Inspect the token system** created by frontend-architecture (Step 1). Understand how tokens are structured (CSS custom properties, theme file, Tailwind config, etc.) and populate the existing system rather than creating a parallel one.
4. If the spec from `docs/visual-design.md` is missing or incomplete, read `references/visual-design-principles.md` and make reasonable, reversible decisions. Note every assumption.

## What you build

Work through these in order, reading the matching reference file for detailed guidance:

1. **Color tokens.** Read `references/color-systems-and-theming.md`. Populate the token system with the project's color palette: primary, secondary, accent, neutral, semantic (success, warning, error, info), surface, and background values. Include dark/light theme values if the spec calls for them.
2. **Typography tokens.** Read `references/typography-and-type-scales.md`. Set up font families, font loading (if needed), type scale, font weights, line heights, and letter spacing as tokens.
3. **Spacing, border, shadow, and surface tokens.** Read `references/hierarchy-and-visual-composition.md`. Populate spacing scale, border radii, shadow values, and surface/overlay tokens.

## What you hand off

After you finish, the token system should have:
- All color values populated and consumable by any component
- Typography fully set up (fonts loaded, scale defined, text utility classes or tokens ready)
- Spacing scale, border, shadow, and surface tokens populated
- Dark/light theme support if the spec requires it

**Do not build any components, layouts, or pages.** That belongs to Steps 3-10. You only populate the design token system.

## Working with other skills

- Frontend Architecture (Step 1) created the token system you're populating
- Structural Layout (Step 3) will use your spacing and surface tokens for page layouts
- UI Components (Step 4) will use your color, typography, and spacing tokens for every component
- All subsequent skills consume your tokens; you are the source of truth for visual values

## Review before finishing

Verify: all tokens from `docs/visual-design.md` are implemented, the token system compiles/builds without errors, font files load correctly (if custom fonts), color contrast meets the accessibility requirements noted in the spec, and no values are hardcoded inline when they should be tokens.

## Boundaries

Don't build page layouts (Step 3). Don't build components (Step 4). Don't add animations (Step 7). Don't restructure the project scaffold (Step 1). You populate the visual token system; everything else uses those tokens.
