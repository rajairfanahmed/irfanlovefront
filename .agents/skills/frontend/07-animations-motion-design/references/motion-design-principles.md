# Motion Design Principles

Motion should explain what changed, where content came from, what action was acknowledged, or how two states relate. It should not compete with reading or delay task completion.

## Use motion for a reason

Good uses include a short state transition, menu disclosure, meaningful progress, spatial continuity, and feedback for an action. Static styling is often sufficient for a simple interaction.

## Define the motion system

Document duration ranges, easing, movement distance, stagger rules, and interruption behavior only when the product uses repeated motion patterns. Keep high-frequency interactions quick. Avoid motion that requires users to wait before acting.

## Match motion to context

A marketing page may use expressive visual transitions, while a data workspace should prioritize speed, focus, and stability. Do not apply one large motion system indiscriminately to all routes.

## Respect user preference

Honor reduced-motion settings and provide equivalent state information without unnecessary movement. Never use flashing or rapid repetitive effects that create discomfort.
