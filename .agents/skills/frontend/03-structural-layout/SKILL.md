# Structural Layout (Step 3 of 10 - Foundation Phase)

**You are Step 3. You run AFTER visual-design (Step 2) and BEFORE ui-components (Step 4).** Steps 1-2 created the project scaffold and populated the design tokens. Your job is to build the global layout structure: page shells, containers, grid system, header/footer skeletons, and section composition.

You own the spatial organization of the application: page architecture, section arrangement, content hierarchy, grids, containers, and alignment. You do not own the visual token values (Step 2), individual component design (Step 4), or responsive adaptation (Step 6).

## Before doing anything: read your spec

1. **Read `docs/structural-layout.md`** - this is your implementation spec generated by the design-engineer skill. It contains all decisions about page compositions, section structure, grid behavior, and spacing relationships. Follow it.
2. **Read `docs/DESIGN_BRIEF.md`** for overall project context.
3. **Read `docs/frontend-architecture.md`** to understand the folder structure and where layout components should live.
4. **Inspect the existing codebase.** Step 1 created the scaffold and Step 2 populated tokens. Use the tokens and folder structure that already exist.

## What you build

Work through these in order, reading the matching reference file for detailed guidance:

1. **Global layout shells.** The main layout wrapper(s) that every page shares: app shell, main content area, sidebar structure if applicable. Read `references/composition-and-hierarchy.md`.
2. **Header and footer structure.** Build the header and footer as layout components (the navigation links and interactive behavior belong to Step 4 UI Components, but the spatial structure and positioning is yours). Read `references/layout-patterns-catalog.md`.
3. **Page containers and grid system.** Set up the container widths, grid columns, gutters, and section spacing that pages will use. Read `references/spatial-rhythm-and-alignment.md`.
4. **Page-level section compositions.** For each page defined in the spec, create the section structure: which sections appear, their order, their spacing, and their container behavior. Read `references/layout-selection-and-tradeoffs.md`.

## What you hand off

After you finish:
- Every page has a layout shell with sections in the correct order
- Header and footer structure exists (content and interactivity will be added by Steps 4-5)
- Grid system and container widths are set up
- Section spacing and alignment uses tokens from Step 2
- Page shells are ready for UI Components (Step 4) to populate with actual components

**Do not build interactive components** (buttons, forms, cards, modals - that's Step 4). **Do not build the navigation menu behavior** (that's Step 4-5). You build the spatial structure; subsequent steps fill it with content and interactivity.

## Working with other skills

- Frontend Architecture (Step 1) defined where layout components live
- Visual Design (Step 2) provided the spacing, surface, and shadow tokens you use
- UI Components (Step 4) will populate your layout sections with actual components
- UX Interaction Design (Step 5) will wire navigation and flow behavior
- Responsive Design (Step 6) will adapt your layouts to different viewport sizes

## Review before finishing

Verify: all pages from the spec have layout shells, header/footer structure matches the spec, spacing uses tokens (no hardcoded values), the grid system works at the default viewport size, and sections are in the correct order per page.

## Boundaries

Don't change the project scaffold (Step 1). Don't change token values (Step 2). Don't build interactive components (Step 4). Don't add responsive breakpoints (Step 6). Don't add animations (Step 7). You build the static spatial structure at the default viewport size.
