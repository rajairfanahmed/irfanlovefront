# Layout Patterns Catalog

Use these patterns as a vocabulary, not a library of mandatory templates. A page may combine patterns when content relationships justify it.

| Pattern | Useful when | Main risk |
|---|---|---|
| Editorial column | reading, policies, long-form content | too narrow for comparison or tools |
| Split feature | two related priorities or media and explanation | poor stacking order on mobile |
| Workspace shell | repeated operational tasks with persistent navigation | excessive chrome and cramped content |
| Data table workspace | scanning, sorting, and comparing records | unreadable columns and weak mobile adaptation |
| Detail with aside | primary record plus contextual actions or metadata | aside becomes overloaded |
| Step-based form | long tasks with meaningful progress stages | excessive navigation and lost context |
| Dashboard overview | several high-value status indicators | meaningless metric tiles and visual noise |
| Gallery or catalog | visual discovery and comparison | inconsistent image crops and filters |
| Documentation layout | nested content and navigation | deep hierarchy and poor mobile navigation |
| Full-bleed narrative | visual storytelling or campaign content | low readability and slow media |

Select the pattern using the page's core task, data density, content length, frequency of use, and device context. Do not force every page into one pattern for superficial consistency.
