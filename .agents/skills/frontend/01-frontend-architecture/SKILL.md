# Frontend Architecture (Step 1 of 10 - Foundation Phase)

**You are Step 1. You run FIRST, before any other frontend implementation skill.** You set up the project scaffold that every subsequent skill builds on top of. Nothing can be implemented until you create the foundation.

You decide how the codebase itself is organized: where components live and how they're grouped, how design tokens become actual code, the project's folder structure and code-quality standards, how state, routing, and data flow through the application, and how the frontend connects to the backend API.

Nothing here assumes a framework, a state management library, a CSS approach, or a folder structure. These are all outcomes of what this specific project already uses or genuinely needs, never a starting assumption.

## Before doing anything: read your spec

1. **Read `docs/frontend-architecture.md`** - this is your implementation spec generated by the design-engineer skill. It contains all decisions about component boundaries, project structure, token system setup, state management, routing, and API client configuration. Follow it. Do not re-decide what it already decided.
2. **Read `docs/api-contract.md`** (or whatever backend API documentation exists in `docs/`) - you need this to set up the API client with the correct base URL, auth headers, error interceptor, and response shapes.
3. **Read `docs/DESIGN_BRIEF.md`** for overall project context.
4. Inspect the actual codebase: the framework and version in use, existing folder layout, existing conventions. Never assume a stack without checking.

## What you build

1. **Project scaffold and folder structure.** Read `references/project-structure-and-code-quality.md`. Create the top-level folder structure, naming conventions, type definitions, linting config, and baseline standards.
2. **Design token system.** Read `references/design-system-implementation.md`. Set up the token architecture (CSS custom properties, theme file, or whatever the stack uses) so that Visual Design (Step 2) can populate the actual values. You create the system; Visual Design fills it with project-specific colors, fonts, and spacing.
3. **Component architecture.** Read `references/component-architecture.md`. Define where components will live, shared vs feature-specific boundaries, and how the organization scales.
4. **API client and data layer.** Wire up the API client based on `docs/api-contract.md`: base URL configuration, authentication header injection, error response interceptor, response type definitions. This is how the frontend talks to the backend.
5. **State and routing.** Read `references/state-routing-and-data-flow.md`. Set up routing structure and state management approach.

## What you hand off

After you finish, the project should have:
- A working folder structure with all directories created
- A token system ready for Visual Design (Step 2) to populate
- An API client configured to talk to the backend
- Routing structure in place
- Type definitions for API responses
- Base layout wrapper components (empty shells that Structural Layout Step 3 will fill)

**Do not build any UI components, pages, or visual styling.** That belongs to Steps 2-10.

## Working with other skills

- Visual Design (Step 2) populates the token system you create here
- Structural Layout (Step 3) builds layouts inside the folder structure you define
- UI Components (Step 4) builds components in the locations you establish
- UX Interaction Design (Step 5) uses the API client and state management you set up
- All subsequent skills inherit your folder conventions, naming patterns, and code-quality standards

## Review before finishing

Check that: the scaffold builds and runs without errors, the token system is set up but awaiting values from Step 2, the API client can be imported and configured, routing works with placeholder pages, and the folder structure matches what `docs/frontend-architecture.md` specified.

## Boundaries

Don't build UI components (Step 4). Don't implement visual tokens with real values (Step 2). Don't build page layouts (Step 3). Don't add animations (Step 7). Don't add SEO metadata (Step 8). You build the foundation; the numbered steps after you build everything else.
