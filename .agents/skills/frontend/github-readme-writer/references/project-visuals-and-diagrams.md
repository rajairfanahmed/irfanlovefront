# Project Visuals and Diagrams

## Choose evidence that helps

A screenshot should show the actual current product and explain an important workflow or visual concept. A demo should be short and readable. A diagram should clarify architecture, data flow, deployment, or module relationships.

## Screenshot quality

Use a relevant viewport, readable scale, realistic but non-sensitive data, and a clean state. Remove user identifiers, tokens, private messages, and internal URLs. Update or remove screenshots when the interface changes.

## Diagrams

Keep diagrams accurate and maintainable. Show only relevant systems and interfaces. Distinguish external services, frontend, backend, storage, and data flow. Do not show an intended architecture as though it were already deployed.

## Asset location

Store project visuals in a predictable repository location and use relative links when appropriate. Check that image paths work from the README's rendered location. Add meaningful alt text and keep file sizes reasonable.
