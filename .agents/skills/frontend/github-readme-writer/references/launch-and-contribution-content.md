# Launch and Contribution Content

## Project maturity

State whether the project is experimental, in active development, stable, archived, or production-ready only when the repository owner can substantiate it. Separate current capabilities from a roadmap.

## Badges

Use badges only when a real source exists and the badge remains maintained. Do not add fake stars, downloads, coverage, license, build, release, or quality indicators. A missing badge is better than an inaccurate one.

## Contribution guidance

Include contribution instructions only when contributions are accepted. Link to real contribution, code-of-conduct, security, and issue templates. Explain local checks and expected review standards where known.

## Support and security

Link to maintained issue, discussion, email, or security-reporting channels only when verified. Do not publish private incident details or encourage users to disclose secrets in public issues.

## Launch writing

Describe the user problem, what the project currently supports, relevant screenshots, setup path, and limitations. Avoid unsupported adoption or performance claims. Keep calls to action specific.
