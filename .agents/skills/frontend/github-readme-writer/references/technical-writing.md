# Technical Writing Standards

## Accuracy

Verify descriptions, versions, commands, scripts, environment variables, routes, and architecture against the repository. Test command examples where practical. Mark uncertain or planned work accurately.

## Clarity

Prefer concrete language, active verbs, and short paragraphs. Define terms when the intended reader may not know them. Use consistent names for packages, features, routes, and commands.

## Useful examples

Provide examples that can run as written or clearly state what must be substituted. Show expected output only when it has been verified. Do not include fake screenshots or fabricated terminal output.

## Writing quality

Avoid inflated adjectives, vague claims, repetitive summaries, forced slogans, and generic statements such as "powerful and seamless". Do not write in a formulaic marketing voice. Do not use em dashes in project documentation.

## Safety

Never publish API keys, private URLs, personal data, internal tokens, or production credentials. Use `.env.example` only with safe placeholder values. Review screenshots for secrets and personal information before committing them.
