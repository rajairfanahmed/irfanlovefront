# WCAG and Accessibility Principles

## Default project target

Use WCAG 2.2 Level AA as the default target unless a contract, jurisdiction, or product requirement specifies otherwise. WCAG 2.2 is a W3C Recommendation and is designed to be backwards compatible with WCAG 2.1 and 2.0. Check the current W3C publication and applicable policy before making a formal conformance statement.

Reference: https://www.w3.org/TR/wcag/

## Apply the four principles

- **Perceivable:** content and controls can be sensed, including alternatives for non-text content and adequate contrast.
- **Operable:** navigation and interactions work with keyboard and other supported inputs, with sufficient time and clear focus.
- **Understandable:** labels, instructions, behavior, and error recovery are clear and predictable.
- **Robust:** semantic output and accessible names work with supported assistive technologies and browsers.

## Conformance discipline

Conformance applies to complete pages and relevant page variations, not a single isolated component. Automated scans can identify some issues but cannot prove full conformance. Manual keyboard, screen-reader, zoom, and content review are required.

## Risk-based review

Prioritize barriers that prevent access to sign-in, navigation, purchases, submissions, reading, and other primary tasks. Record exclusions and unresolved issues transparently.
