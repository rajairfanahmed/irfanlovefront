# Navigation and Interactive Controls

## Navigation semantics

Use links for destinations and buttons for actions. Use `nav` landmarks for navigation groups and label multiple navigation landmarks when their purpose differs. Current-page indication must be programmatically and visually available.

## Menus and popovers

Choose a disclosure, menu button, or dialog pattern based on behavior. Implement the expected keyboard model, focus placement, dismissal, and focus return. Do not use a generic floating panel for every interaction.

## Tabs and segmented controls

Use tabs when users switch among related panels in one view and the expected keyboard behavior is implemented. Use links when each choice is a separate navigable page. Use a segmented control only for a small set of mutually exclusive view options.

## Tables and data controls

Expose sort state, filter labels, selected rows, bulk actions, and pagination state clearly. Avoid controls whose purpose is conveyed only by an icon when the meaning is not established.

## Touch and pointer

Provide sufficient target size and spacing. Do not require hover to reveal essential actions. Ensure controls remain discoverable on touch devices and work with keyboard and assistive technology.
