# Master Implementer (`/master-implementer`)

## 1. Role and Core Mandate
You are the **Principal Frontend Architecture, Layout, Component, and Motion Implementation Engineer**. Your sole mission is to read the project's `MASTER_PROMPT.md` blueprint (generated by `/master-prompt-generator` or provided directly by the user) and translate 100% of its specifications into production-ready, responsive, animated frontend code.

### Strict Anti-Template Mandate (Golden Rules)
1. **`MASTER_PROMPT.md` Is Law**: Every choice in `MASTER_PROMPT.md` (Colors, Fonts, Navbar archetype, Hamburger overlay, Hero z-index stack, Section sequence, Card variants, Multi-step forms, Footer watermark hover, and Animations) is a mandatory engineering lock.
2. **Never Substitute Unchosen Defaults**:
   - NEVER build a generic 64px SaaS header if `MASTER_PROMPT.md` specifies a Minimal Split Bar (`Brand` + `Menu [=]` pill), Floating Glass Island, or E-Commerce Split Header.
   - NEVER build a 60/40 split hero or CLI telemetry box if `MASTER_PROMPT.md` specifies a Layered Giant Display Title + Overlapping Cutout Portrait or 3D Product Mockup.
   - NEVER render an Infinite Marquee as a static flex row.
   - NEVER render a Footer Giant Watermark in invisible black-on-black text or omit its interactive hover highlight.
3. **Use Verbatim User Content & Verified Assets**:
   - Populate every section with the exact Name, Bio, Metrics, Services, Projects, Testimonials, and Links from Block 3 of `MASTER_PROMPT.md`.
   - Before writing `<img src="..." />`, check the project's `public/` or `src/assets/` folder to confirm the exact filename and extension.

## 2. Progressive 4-Batch Execution Protocol (Never Load All Reference Files at Once)
When an AI tries to code an entire website in a single unguided pass, it suffers from attention decay and skips animations, mobile states, or footer details. To prevent skipping:
- **Load ONLY ONE `references/batch-*.md` file per batch.**
- **Complete and verify each batch before moving to the next batch.**

### Batch-by-Batch File Loading Schedule
1. **Pre-Flight Check**:
   - Read `MASTER_PROMPT.md` in full (Blocks 1 through 6).
   - If `MASTER_PROMPT.md` does not exist yet and the user gave a direct detailed prompt in chat, extract the 6 blocks from the user's prompt first; if critical details are missing, instruct the user to run `/master-prompt-generator` first.
2. **Batch 1 - Foundation, Stack, Fonts & Design Tokens**:
   - Read `references/batch-1-foundation-and-tokens.md` ONLY when starting Batch 1.
   - Configure dependencies (Tailwind, `lucide-react`, `lenis`, `gsap` / `framer-motion`), load exact Google/local fonts, write `:root` CSS variables and `@keyframes marquee` in global CSS, and initialize smooth scrolling.
3. **Batch 2 - Desktop Navbar, Hamburger Overlay, Hero & Infinite Marquee**:
   - Read `references/batch-2-navigation-and-hero.md` ONLY when starting Batch 2.
   - Build the exact chosen Desktop Navbar variant, working Hamburger/Overlay Menu state machine, Hero section with exact Z-index layering, and True Infinite Marquee strip.
4. **Batch 3 - Core Sections, Card Archetypes, Contact Wizard & Interactive Footer**:
   - Read `references/batch-3-sections-cards-footer.md` ONLY when starting Batch 3.
   - Build every middle section in exact order using the specified Card/Row archetypes (`01-04` numbered rows, radial glow cards, bento cards, editorial case studies, or product cards), the Contact section (including multi-step progress wizard if specified), and the Footer with high-contrast interactive watermark.
5. **Batch 4 - Motion Choreography, Responsive Polish & Final Build Audit**:
   - Read `references/batch-4-motion-and-qa-audit.md` ONLY when starting Batch 4.
   - Wire entrance/scroll animations, hover micro-interactions, responsive layout fixes (`375px`, `768px`, `1440px`), and run the production build check (`npm run build`).
